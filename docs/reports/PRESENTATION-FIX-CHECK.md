## สิ่งที่ยังต้องตรวจด้วยสภาพแวดล้อมจริงก่อนพรีเซนต์

1. เปิด Supabase ให้พร้อม และรอ Resume เสร็จ ก่อนเปิดแอป
2. รันแอปจาก branch `fix` ด้วย `npm run dev`; ตรวจ URL/พอร์ตที่แสดงใน terminal
3. หากใช้ Cloudflare Quick Tunnel ต้องเปิด process ทิ้งไว้ และตรวจว่า hostname ใน `vite.config.ts` ตรงกับ URL ปัจจุบัน
4. เตรียมภาพพืชชัดเจนหลายภาพ และทดสอบรูปที่จะใช้จริงก่อนวันพรีเซนต์ ค่าความมั่นใจขึ้นอยู่กับภาพและบริการระบุพืช
5. ยืนยันว่ากล้องและการเลือกรูปใช้ได้บนอุปกรณ์ที่จะนำเสนอ การทดสอบจำลองไม่แทนการทดสอบกล้องจริง
6. ตรวจโควตาบริการจริงก่อนเริ่ม; fallback ช่วยให้แอปไม่พังเมื่อ Gemini ล้มเหลว แต่ไม่ได้ทำให้ API มีโควตาเพิ่มหรือสร้างคำแนะนำที่ขาดอยู่
7. ถ้าต้องการใช้ audit metadata ใหม่บนระบบจริง ต้อง deploy ชุด server นี้แยกต่างหากโดยรักษา Demo dataset route ของ hosted function ปัจจุบัน

## ข้อจำกัดที่คงไว้

- การ abort ฝั่ง browser ไม่รับประกันว่า Edge Function หรือบริการภายนอกที่เริ่มทำงานแล้วจะหยุด และอาจมีการใช้โควตาไปแล้ว ภาพที่อัปโหลดแล้วจะพยายามลบเมื่อคำขอยกเลิก/ล้มเหลว แต่หากเครือข่ายขัดข้อง cleanup อาจไม่สำเร็จ
- การควบคุมโควตาสแกนพร้อมกันแบบ atomic และการแบ่งหน้าข้อมูลยังเป็นงานถัดไป ไม่แก้ schema หรือเปลี่ยนเส้นทางฐานข้อมูลในรอบเตรียมสาธิตนี้
- ยังไม่ได้ทำ load test, ทดสอบมือถือจริง หรือทดสอบ hosted APIs ซ้ำในรอบนี้ และไม่มีการรับรองว่า API ภายนอกจะพร้อมทุกเวลา
